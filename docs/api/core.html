Core

The FastHTML subclass of Starlette.

Create an app with app = FastHTML(). The @rt decorator adds routes (rt = app.route), inferring what it can from the function:

@rt
def index(): ...      # GET,POST /
@rt
def foo(): ...        # GET,POST /foo
@rt('/hi')
def get(): ...        # GET /hi (function named after a verb handles just that verb)
@rt('/cards/{id}')
class Cards: ...      # class route group: each verb-named method (get, patch, ...) becomes a handler

The decorated function doubles as a URL builder, so links never need hardcoded paths:

A('More', href=foo.to(a=1))   # <a href="/foo?a=1"> `.to()` fills path params; the rest become query params.
Div('...', hx_get=foo)        # route functions work directly as htmx attr values: hx-get="/foo"

Handlers return FT trees (from fastcore.xml), rendered as HTML automatically: a full page for regular requests, a bare fragment for HTMX requests. In a full page, top-level Title, Meta, Link, and Style items go in <head>; the rest goes in <body>. Strings are sent as HTML, dicts as JSON, and a Starlette Response is sent untouched. A return tuple may mix content with special items: any HttpHeader (e.g. from cookie() or HtmxResponseHeaders()) becomes a response header, any BackgroundTask runs after the response is sent, and the rest renders as content. Redirect picks the right redirect mechanism for HTMX vs regular requests, and FtResponse wraps FT content when you need the status code or headers.

Handler parameters are filled from the request: each is looked up in path, cookie, header (snake_case names match Hyphen-Case headers), query, then form data, and cast by calling its annotation on the value. Hyphens in form/query names match underscores in handler parameters and typed body fields. Exact names take precedence within each source. Dictionary and request access retain the original keys. bool, int, and date get smart string parsing; UploadFile passes through. Repeated params take the last value unless annotated list[T], which collects them all. A param with no annotation and no special name is ignored, with a warning. A dataclass, TypedDict, namedtuple, or any annotated class collects the whole form body; a __from_request__ classmethod customizes construction. A missing required param is a 400, a failed cast a 404. These special names need no annotation:

req, ws   the Request / WebSocket connection
sess      session dict
app       the FastHTML app
state     app.state
scope     ASGI scope
auth      scope['auth']
htmx      HtmxHeaders (parsed HX-* request headers)
body      raw body text
data      parsed form data as a dict
api       ApiReturn (API vs browser dual responses)
send      websocket send function
hdrs,ftrs the per-request copies of the app's `hdrs`/`ftrs` (head and footer content)
htmlkw    the per-request copy of the app's `<html>` attrs
bodykw    the per-request copy of the app's `<body>` attrs
resp      the handler's response (injected into `after` functions)

before/after functions (app-level, with Beforeware skip patterns, or per-route before=) get the same param injection as handlers. A before returning a value responds with it and skips the handler (the usual auth-guard pattern).

See the Handling Handlers tutorial for worked examples of the above.

This is the source code to fasthtml. You won’t need to read this unless you want to understand how things are built behind the scenes, or need full details of a particular API. The notebook is converted to the Python module fasthtml/core.py using nbdev.

ApiReturn

def ApiReturn(
    isapi:bool=False
):

Request param: call with browser and API responses; returns kwargs as JSON if the client accepts application/json, else norm

Routes often need to return different responses depending on whether the request comes from a browser or an API client. The api:ApiReturn parameter handles this automatically — add it to any route signature and call it with two arguments: the API response and the browser response. If the request’s Accept header is application/json then a dict of the kwargs is returned, otherwise, the first value is returned. For example, return api(Redirect('/records'), id=record.id) returns {‘id’:id} for API callers and a redirect for the browser. This keeps your route logic in one place instead of splitting it across separate endpoints.

serve

def serve(
    appname:NoneType=None, # Name of the module
    app:str='app', # App instance to be served
    host:str='0.0.0.0', # If host is 0.0.0.0 will convert to localhost
    port:NoneType=None, # If port is None it will default to 5001 or the PORT environment variable
    reload:bool=True, # Default is to reload the app upon code changes
    procs:NoneType=None, # Processes to run on consecutive ports from `port`; default 1 or the PROCS environment variable
    **kwargs
):

Run the app in an async server, with live reload set as the default.

procs runs the app as that many processes on consecutive ports from port, each with its own reload supervisor, and defaults to the PROCS environment variable. serve re-executes the script once per process with FH_PROCNUM set to its number, which is also the guard against a child spawning again. An app reads FH_PROCNUM for work that only one process should do, such as a background job: it is '0' in the first process, and unset in an ordinary single-process run. A reverse proxy in front of the ports decides how requests reach them.

Starlette does not cancel a running handler when a client disconnects: the disconnect is only visible as an http.disconnect message on the ASGI receive channel, which ordinary handlers never read. until_disconnect races a coroutine against that message, cancelling the work if the client goes away first.

until_disconnect

Await coro, cancelling it (and returning an empty response) if the client disconnects first

cancel_on_disconnect applies this to a route handler. splice_sig adds a private Request-annotated parameter to the exposed signature, which FastHTML fills with the connection, so the handler’s own parameters are unchanged. It requires an async handler, since a sync handler runs in a threadpool and cannot be cancelled.

)->None:

StaticImmutable

def StaticImmutable(
    *, directory:PathLike | None=None, packages:list[str | tuple[str, str]] | None=None, html:bool=False,
    check_dir:bool=True, follow_symlink:bool=False
)->None:

Like StaticNoCache, but marks responses as cacheable forever: for versioned URLs such as vurl links or content-hashed filenames

These two classes are the poles of static-file caching. StaticNoCache makes the browser revalidate on every use: always fresh at the cost of a conditional request each time, right for files that change under a stable URL (and for dev, where you want edits visible on reload). StaticImmutable promises the URL’s content will never change, so the browser may cache it forever with no requests at all: only safe when a changed file gets a changed URL, which is what vurl or a bundler’s content-hashed filenames provide.

statd = Path(tempfile.mkdtemp())
(statd/'app.css').write_text('body{}')
stat_app = FastHTML(routes=[Mount('/nc', StaticNoCache(directory=statd)), Mount('/imm', StaticImmutable(directory=statd))])
stat_cli = TestClient(stat_app)
test_eq(stat_cli.get('/nc/app.css').headers['cache-control'], 'no-cache')
test_eq(stat_cli.get('/imm/app.css').headers['cache-control'], 'public, max-age=31536000, immutable')

vurl

def vurl(
    path, root:str='.'
):

Return path as a URL with a v query param hashing the file’s contents, so the URL changes when the file does

Browsers use the URL as the cache key, so a URL that changes whenever the file’s contents change can be cached forever: serve the mount with StaticImmutable and the asset costs no requests at all until it is next edited. This is the query-param version of the content-hashed filenames that asset pipelines and bundlers produce, without the build step. The hash is cached via flexicache with mtime_policy, so a call costs one stat and the file is only re-read after it changes. The param is inert under no-cache serving, so the same links work in dev with StaticNoCache, where the file is rechecked on each reload.

tmp = Path(tempfile.mkdtemp())
(tmp/'a.css').write_text('body{}')
u = vurl('a.css', tmp)
assert u.startswith('a.css?v=')
test_eq(u, vurl('a.css', tmp))
test_eq(vurl('/a.css', tmp).split('?')[0], '/a.css')
q = vurl('/a.css?theme=dark#top', tmp)
assert q.startswith('/a.css?theme=dark&v=') and q.endswith('#top')
(tmp/'a.css').write_text('body{color:red}')
os.utime(tmp/'a.css', (time.time()+1,)*2)
assert vurl('a.css', tmp) != u

into

def into(
    func
):

Decorator to pass a route’s return value into func, with keyword params added to the route signature

into is a decorator that composes two functions: the decorated route function and an outer “wrapper” function (like a layout). The route’s return value is passed as positional args to the wrapper. Any keyword parameters listed in params are added to the route’s signature, so they become available as query/form parameters. This lets you write simple routes that return just their content, while the layout and its parameters are handled automatically.

Here hello returns a single P tag, but into(my_layout) passes it into my_layout, which wraps it in a Titled. The title parameter is injected into hello’s signature so it can be set via query params.

app,cli,rt = get_cli(FastHTML())

def my_layout(*c, title:str='Default'): return Titled(title, *c)

@rt
@into(my_layout)
def hello(name:str='World'): return P(f'Hello, {name}!')

With no query params, name defaults to 'World' and title defaults to 'Default' (from my_layout’s own default), giving us a page titled “Default” containing “Hello, World!”.

r = cli.get('/hello')
assert '<title>Default</title>' in r.text
assert '<p>Hello, World!</p>' in r.text

Here, both name and title are provided as query params. name='Jeremy' is handled by hello directly, while title='Greetings' is the injected param that gets forwarded to my_layout.

r = cli.get('/hello?name=Jeremy&title=Greetings')
assert '<title>Greetings</title>' in r.text
assert '<p>Hello, Jeremy!</p>' in r.text
